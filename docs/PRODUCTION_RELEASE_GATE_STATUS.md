## Gate-closing rule

A release gate can move to **CLOSED** only when all of the following are attached or linked: (1) implementation evidence, (2) automated or reproducible acceptance evidence, (3) failure-path evidence, and (4) operational evidence where the gate depends on deployed behavior. Documentation alone is not closure.

## Immediate reliability sequence

1. Wire the independent policy/Target Scope Guard and receipt emission into every production external-write adapter; the machine-readable capability contract now requires this, but registry compliance alone is not runtime proof.
2. Replace the single-host filesystem reference backend with a production multi-host atomic CAS/transaction implementation (database or Redis) while preserving the current claim/complete contract.
3. Define claim lease/expiry and recovery semantics, especially the crash window where a provider write may have succeeded but local completion was not recorded.
4. Implement connector-specific idempotency-key derivation plus provider verification/reconciliation, then persist the action receipts that drive the policy-coverage metrics.
5. Add multi-host contention, crash-after-provider-write, timeout ambiguity, restart/recovery, tenant-negative, policy-bypass, and provider-reconciliation fault-injection tests.
6. Stand up production telemetry/alerts plus incident/rollback and backup/restore drills, then re-evaluate this matrix before making production/commercial reliability claims.
